# Price book v6: two proposed rows for the Form 990 family (proposal, 2026-09-27, R66)

Proposal only; nothing is published and no seed changes. Brian sets the amounts and publishes the
version from Admin → Pricing; a price appearing as a literal in application code is a build failure
(CLAUDE.md), so this file names the rows and leaves the dollars to the book.

## What v5 prices today

`BIZ_990` — "Form 990 / 990-EZ — exempt organization" / "Formulario 990 / 990-EZ — organización
exenta" (`packages/db/seeds/data/price_book.mjs:235`), service line `business_tax`, group
`business_returns` (sort 40), unit `flat`, with the business deposit. It is the base return item for
**both** the 990 and the 990-EZ: since R66 the item → return-type map carries `covers: ['990', '990ez']`
(`apps/api/src/modules/tax/return-type.ts`), so a 990-EZ return reads its quoted range from BIZ_990
through `quotedRangeFor` (`apps/api/src/modules/tax/routes.ts`), while an accepted quote holding
BIZ_990 still creates a **990** return — the preparer decides the short form on the return itself.

`990pf` and `990t` are in the return-type enum (migration 0125), derive their deadlines from the
authoritative table (the 15th day of the fifth month after the fiscal year end, +6 months on Form
8868), and take the 8879-TE at upload. They have **no price-book line**: a quote cannot name them and a
990-PF or 990-T return opened by hand has no quoted range until one exists.

## The two rows proposed for v6

| code | name (EN) | name (ES) | service line | group | unit | deposit | proposed amount |
|---|---|---|---|---|---|---|---|
| `BIZ_990PF` | Form 990-PF — private foundation | Formulario 990-PF — fundación privada | `business_tax` | `business_returns` (sort 42) | `flat` | the business deposit rule (`bizDeposit`), as every other business return | **Brian's to set** — the 990-PF carries the excise-tax computation and the investment schedules the 990 does not; the seed's BIZ_990 amount is the floor |
| `BIZ_990T` | Form 990-T — unrelated business income | Formulario 990-T — ingresos comerciales no relacionados | `business_tax` | `business_returns` (sort 44) | `flat` | the business deposit rule (`bizDeposit`) | **Brian's to set** — usually filed beside a 990 for the same organization; priced as its own return, not an add-on, because it is its own form with its own deadline |

Both rows: `display_on_quote` true, `is_active` true, `needs_confirmation` false, `price_min/max` null
(flat), the same 8868 extension and 8879-TE the rest of the family takes.

## What publishing them turns on (no code needed beyond the map entry)

1. Add the two rows to the v6 seed data / publish v6 from Admin → Pricing with Brian's amounts.
2. Add `BIZ_990PF: { returnType: '990pf', clientType: 'nonprofit' }` and
   `BIZ_990T: { returnType: '990t', clientType: 'nonprofit' }` to `BASE_ITEMS` in
   `apps/api/src/modules/tax/return-type.ts` so an accepted quote creates the right return and the
   return reads its range from its own line. (Left out of this batch on purpose: a map entry for a
   line that does not exist would make `quotedRangeFor` look up a row the book does not hold.)
3. `groupFor` in `packages/db/seeds/data/price_book_groups.mjs`: `BIZ_990PF: g('business_returns', 42)`,
   `BIZ_990T: g('business_returns', 44)`.
